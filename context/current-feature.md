# Current Feature: Sidebar Redesign — "Ledger" Design System

## Status

In Progress

## Goals

- Restyle `SidebarNav.tsx` (and `Sidebar.tsx`'s own wrapper chrome around it) to match
  `prototypes/redesign/kept-dashboard.html`'s sidebar treatment, currently only inheriting
  color tokens with no component-level restyle (an explicit scope cut from the 2026-08-25
  dashboard redesign pass).
- Section labels ("Item Types", "Favorite Collections", "Recent Collections") become
  uppercase, letter-tracked, with a dotted-divider underline — matching the section-header
  convention already used elsewhere (`context/design-system.md`'s "Typography conventions").
- Item-type rows: icon rendered inside a soft-tint colored chip square (`withAlpha()`, same
  pattern as `ItemCard`/`CollectionCard`), not a bare colored icon.
- Item-type counts become zero-padded, tabular (`04` not `4`), right-aligned — matching the
  stat/count convention used on `StatsCards`/`DashboardGridSection`.
- Zero-item types render dimmed (reduced opacity) instead of full-strength, still visible and
  clickable — no "hide zero-count types" toggle (that was a canvas-editor authoring knob in
  the mockup, not a product feature; `getItemTypes()` already returns all types including
  zero-count ones, so this is styling only).
- Favorite Collections / Recent Collections rows: replace the current `Star` icon (favorites)
  and plain circle (recent) with the mockup's small square/dot marker treatment.
- "Navigation" header row (label + collapse toggle) restyled to match the label convention
  above; keep the existing `PanelLeftClose`/`PanelLeftOpen` collapse behavior as-is
  (functional parity, icon choice unchanged — mockup doesn't specify a different icon).

## Notes

- Explicitly **out of scope** this pass (per user decision when this was scoped): TopBar's
  "New Collection"/"New Item" buttons and search input styling, `UserFooter`'s avatar
  (square-initials vs. current circular `UserAvatar`), and the Light/Dark appearance toggle
  (real new functionality — no light-mode implementation exists yet, `design-system.md`
  confirms the app is hardcoded dark). Do not touch those in this pass.
- Source of truth: `prototypes/redesign/kept-dashboard.html` (static HTML/inline styles) —
  `prototypes/redesign/support.js` is the generic Claude Design canvas runtime that made the
  mockup interactive in-editor (theme swatches, click-to-open-drawer demo behavior); it has no
  app-specific styling to port and should not be treated as a spec.
- `SidebarNav.tsx` is shared by both desktop `Sidebar.tsx` and `MobileSidebar.tsx` (via its
  `comfortable` prop for touch-sized rows) — restyling it ripples into the mobile drawer too,
  per the project's established "redesign shared components in place" convention
  (`context/design-system.md` engineering principle #2). Verify the mobile drawer still reads
  correctly (44px `comfortable` row height not fighting the new label/chip treatment) before
  calling this done.
- `getItemTypes()` (`src/lib/db/items.ts`) already returns all item types including
  zero-count ones, sorted by count descending — no data-layer change needed, dimming is a
  className-only condition on `type.itemCount === 0`.
- Favorite-collection markers: mockup uses a plain filled square (`--accent` colored); current
  uses a yellow filled `Star`. Recent-collection markers: mockup uses a small square dot
  colored per-collection (`collection.borderColor`); current already uses a colored circle
  (`rounded-full`) — close, just shape (circle vs. square) differs from the mockup's square
  dot convention used elsewhere (e.g. favorite-marker dot on `ItemCard`/`CollectionCard`).
- No schema/server-action changes anticipated — this is a UI-only restyle in
  `src/components/dashboard/SidebarNav.tsx` and `Sidebar.tsx`, so no new tests expected
  (matching the project's established pattern for prior redesign passes).
